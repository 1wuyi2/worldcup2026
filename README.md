# WorldCup2026

> 每一场比赛，都值得铭记。

WorldCup2026 是南开大学《互联网数据库开发》课程的三人团队课程设计项目，以 2026 FIFA 世界杯为主题，基于 Yii2 Advanced 架构构建，集世界杯赛事数据、新闻资讯、团队门户及后台内容管理于一体。

项目采用前后台分离的应用结构，通过 MariaDB 实现业务数据的统一存储与管理，并结合用户认证、RBAC 权限控制、动态数据查询及响应式页面设计，构建具有完整业务流程的数据库驱动型网站。

### 1.1 设计理念

网站前台采用 Midnight Pitch 视觉体系，以深色背景、荧光绿色及体育媒体风格为主要视觉特征，并根据不同业务模块设计相应的内容展示方式。

- 首页突出世界杯赛事氛围与网站核心内容。
- 足球数据模块强调赛事信息、比分及数据之间的关联。
- 新闻资讯模块采用编辑式新闻页面布局，注重内容阅读体验。
- 团队门户采用相对独立的浅色视觉体系，突出成员资料与课程成果。
- 后台采用深色侧边栏与浅色工作区，强调信息可读性及管理效率。

各模块在保持独立视觉特色的同时，共享统一的品牌标识、导航结构及基础交互规范。

## 2. 功能模块

项目由团队门户、新闻资讯和足球数据三个核心业务模块组成，并提供统一的用户认证与后台管理体系。

### 2.1 模块 A：团队门户

用于展示团队信息、成员资料及课程设计成果。

主要功能：

- 团队基本信息及项目介绍。
- 团队成员展示。
- 成员独立个人主页。
- 成员个人介绍及项目职责展示。
- 团队作业与个人作业分类归档。
- 课程资料筛选及文件下载。
- 团队寄语与个人学习心得展示。
- 留言分类筛选与分页。
- 后台团队、成员、作业及留言管理。
- 作业资源上传与成员关联。
- 留言发布状态管理。

团队门户中的成员资料、作业及留言均通过后台统一维护，前台负责公开展示。

### 2.2 模块 B：新闻资讯

用于管理和展示世界杯相关的新闻内容。

主要功能：

- 新闻文章列表及详情展示。
- 焦点新闻与最新资讯展示区域。
- 新闻分类及标签管理。
- 新闻关键词搜索。
- 分类、标签及新闻状态筛选。
- 新闻摘要、正文、来源及发布时间展示。
- 后台新闻文章新增、编辑及删除。
- 新闻草稿、发布及撤稿管理。
- 新闻文章与标签的多对多关联。

新闻模块的基础业务功能及前台展示结构已经实现，正式新闻数据正在整理，完整展示效果将在真实数据集成后进行验收。

### 2.3 模块 C：足球数据

围绕 2026 FIFA 世界杯构建关联式足球数据管理与展示模块。

主要功能：

- 世界杯赛事中心。
- 比赛赛程、比分及比赛详情展示。
- 小组赛及淘汰赛信息展示。
- 淘汰赛对阵图。
- 参赛国家队列表及球队详情。
- 球员列表及球员详情。
- 球员与所属球队关联。
- 世界杯场馆列表及场馆详情。
- 基于 Leaflet 的交互式场馆地图。
- 比赛与参赛球队、比赛场馆关联。
- 比赛进球记录管理。
- 后台比赛、球队、球员、场馆及进球记录维护。

足球数据模块通过数据库关联关系组织赛事信息，实现不同业务页面之间的联动浏览。

## 3. 用户认证与权限管理

项目采用 Yii2 用户认证机制及 RBAC 权限管理体系。

### 3.1 前台用户

- 用户注册及账号激活。
- 用户登录与退出登录。
- 记住登录状态。
- 表单输入验证及中文错误提示。
- 密码安全存储。
- 登录后的账户下拉菜单。
- 根据用户管理权限动态展示后台访问入口。

普通注册用户不自动获得后台管理权限。

### 3.2 后台用户

后台采用独立的登录页面及 Session 管理机制。

只有具备相应业务管理权限的账号才能访问后台系统。

当前业务权限划分如下：

| 权限名称 | 管理范围 |
| --- | --- |
| `managePortal` | 团队门户管理 |
| `manageNews` | 新闻资讯管理 |
| `manageFootball` | 足球数据管理 |

后台通过 RBAC 权限检查控制模块访问，并根据当前账号的实际授权动态生成管理导航。

前后台共享用户数据及权限体系，但保持独立的登录状态。前台登录不会自动完成后台登录。

### 3.3 后台管理系统

后台提供统一的管理界面，包括：

- 基于权限的模块导航。
- 管理工作台。
- 数据库真实业务记录统计。
- 业务管理快捷入口。
- 数据列表、搜索、筛选及分页。
- 新增、编辑、详情及删除页面。
- 文件上传与表单验证。
- 统一的操作反馈及状态提示。
- 前后台双向访问入口。

工作台统计数据通过实际数据库查询获得，并根据当前管理员权限确定可见范围。

## 4. 系统架构

项目采用 Yii2 Advanced 应用结构，将前台展示、后台管理、公共业务模型和控制台维护功能进行划分。

```text
                         浏览器
                            |
                +-----------+-----------+
                |                       |
            前台应用                 后台应用
           frontend                   backend
                |                       |
                +-----------+-----------+
                            |
                     共享业务模型
                         common
                            |
                 +----------+----------+
                 |          |          |
              模块 A      模块 B      模块 C
              团队门户    新闻资讯    足球数据
                 |          |          |
                 +----------+----------+
                            |
                         MariaDB
                            |
                  Migration / SQL / RBAC
```

主要技术实现：

- 使用 MVC 架构分离业务逻辑、数据模型与页面展示。
- 使用 ActiveRecord 完成数据库查询及业务数据维护。
- 使用数据库主键、外键及关联表建立业务实体关系。
- 使用 Migration 管理数据库结构版本。
- 使用 RBAC 实现业务模块权限隔离。
- 使用 AssetBundle 管理 CSS、JavaScript 等静态资源。
- 使用 Bootstrap、GridView、ActiveForm 等组件构建后台管理功能。
- 使用自定义 CSS 和 JavaScript 完成前台视觉设计与交互。

## 5. 数据库设计

项目数据库由用户认证、权限管理及三个业务模块组成。

### 5.1 团队门户

主要业务表：

| 数据表 | 用途 |
| --- | --- |
| `wc_portal_team` | 团队基本信息 |
| `wc_portal_member` | 团队成员信息 |
| `wc_portal_assignment` | 团队及个人课程作业 |
| `wc_portal_message` | 团队及个人留言 |

团队、成员、课程作业及留言之间通过关联字段建立业务关系。

### 5.2 新闻资讯

主要业务表：

| 数据表 | 用途 |
| --- | --- |
| `wc_news_category` | 新闻分类 |
| `wc_news_article` | 新闻文章 |
| `wc_news_tag` | 新闻标签 |
| `wc_news_article_tag` | 新闻与标签关联 |

新闻分类与文章之间为一对多关系，新闻文章与标签之间通过中间表建立多对多关系。

### 5.3 足球数据

主要业务表：

| 数据表 | 用途 |
| --- | --- |
| `wc_football_team` | 参赛球队 |
| `wc_football_player` | 球员信息 |
| `wc_football_stadium` | 比赛场馆 |
| `wc_football_match` | 比赛信息 |
| `wc_football_match_goal` | 比赛进球记录 |

足球模块围绕比赛、球队、球员、场馆及进球记录构建关联式数据结构。

### 5.4 用户与权限

用户认证及权限管理主要使用 Yii2 提供的数据结构：

- `user`
- `auth_item`
- `auth_item_child`
- `auth_assignment`
- `auth_rule`

数据库实际字段、索引、约束及关联关系以 `console/migrations/` 中的迁移文件为准。

## 8. 本地安装与运行

### 8.1 克隆仓库

```cmd
git clone https://github.com/1wuyi2/worldcup2026.git

cd worldcup2026
```

协作开发时，按实际开发任务切换至对应分支。

### 8.2 安装 Composer 依赖

```cmd
composer install
```

如果 PHP 或 Composer 未配置到 PATH，可以通过本机实际安装路径执行。

例如：

```cmd
D:\xampp\php\php.exe D:\tools\composer\composer.phar install
```

生产环境不需要测试及代码生成工具时，可执行：

```cmd
composer install --no-dev
```

### 8.3 初始化 Yii 环境

Windows 环境执行：

```cmd
init.bat
```

选择 Development 环境。

初始化会根据 `environments/dev/` 中的配置模板生成本地配置文件，并生成应用所需的 cookieValidationKey。

如果项目已经完成初始化，不应随意覆盖现有本地配置。

### 8.4 配置数据库

启动 XAMPP 中的 Apache 和 MariaDB 服务。

创建本地开发数据库，编辑：

```text
common/config/main-local.php
```

根据本机环境配置数据库连接，例如：

```php
'db' => [
    'class' => 'yii\db\Connection',
    'dsn' => 'mysql:host=127.0.0.1;port=3307;dbname=YOUR_DATABASE_NAME',
    'username' => 'YOUR_DATABASE_USER',
    'password' => 'YOUR_DATABASE_PASSWORD',
    'charset' => 'utf8mb4',
],
```

数据库名称、用户名及密码应替换为本机实际配置。

不要将真实数据库凭据提交到 Git 仓库。

### 8.5 初始化数据库

项目使用 Migration 管理数据库结构，同时在 `data/` 目录维护数据库初始化脚本。

全新数据库可以依据 `data/README.md` 导入对应版本的 `data/install.sql`。

已有数据库应先备份，再根据项目当前版本执行尚未应用的 Migration：

```cmd
php yii migrate
```

如果 PHP 未加入 PATH：

```cmd
D:\xampp\php\php.exe yii migrate
```

数据库初始化脚本可能与当前开发进度存在版本差异，正式部署时应使用与最终交付版本匹配的 SQL 文件。

不要将完整初始化脚本直接导入已有业务数据的数据库，以免造成主键冲突或数据覆盖。

详细说明见：

[数据目录说明](data/README.md)

### 8.6 初始化后台权限

后台管理功能依赖 RBAC 权限配置。

完成数据库初始化后，需要按照项目控制台权限管理命令及相关文档，为管理账号配置对应业务权限。

普通注册账号不会自动获得后台管理权限。

### 8.7 访问网站

使用 XAMPP 默认目录映射时，将项目放置于：

```text
D:\xampp\htdocs\worldcup2026
```

即可通过以下地址访问。

| 应用 | 地址 |
| --- | --- |
| 前台网站 | `http://localhost/worldcup2026/frontend/web/index.php` |
| 前台登录 | `http://localhost/worldcup2026/frontend/web/index.php?r=site/login` |
| 前台注册 | `http://localhost/worldcup2026/frontend/web/index.php?r=site/signup` |
| 后台系统 | `http://localhost/worldcup2026/backend/web/index.php` |
| 后台登录 | `http://localhost/worldcup2026/backend/web/index.php?r=site/login` |

前后台跳转入口统一通过公共配置管理：

```text
common/config/params.php
```

如使用不同的项目目录、域名或 VirtualHost，需要同步调整 `frontendBaseUrl` 和 `backendBaseUrl`。

个人环境配置可以通过对应的本地配置文件覆盖，不应随意修改其他成员的运行环境。

## 9. 数据库维护与数据集成

### 9.1 数据库结构维护

开发过程中以 `console/migrations/` 中的 Migration 作为数据库结构变更依据。

新增或调整数据库字段时，应：

1. 创建新的 Migration。
2. 在独立测试数据库中验证。
3. 检查主键、外键、索引及业务兼容性。
4. 经团队确认后进行合并。
5. 在备份数据库后执行批准的 Migration。

不要随意修改已经共享并执行的历史 Migration。

### 9.2 模块数据集成

三个业务模块可以在各自的开发环境中独立进行数据准备及录入。

集成时应提供：

- 对应业务模块的数据 SQL。
- 新增数据库结构所需的 Migration。
- 与数据库记录对应的图片或文件资源。
- 必要的代码更新及说明。

数据合并前应检查：

- 表结构是否兼容。
- 主键是否存在冲突。
- 外键及逻辑关联是否完整。
- 文件路径与实际资源是否一致。
- 是否混入临时测试数据或本地敏感配置。

不要使用某个成员的完整开发数据库直接覆盖团队集成数据库。

最终数据库初始化脚本将在全部真实业务数据集成及验收后统一整理。

## 10. 团队协作与 Git 规范

项目采用 Git 和 GitHub 进行版本管理。

### 10.1 分支约定

| 分支 | 用途 |
| --- | --- |
| `main` | 稳定、可演示版本 |
| `dev` | 团队集成分支 |
| `frontend-design` | 前端设计、公共布局及项目界面集成 |
| `feature/<模块>-<功能>` | 业务功能开发 |
| `fix/<问题>` | 缺陷修复 |
| `docs/<主题>` | 文档维护 |

各模块开发及集成应保持明确的修改范围，避免不同成员同时覆盖公共文件。

### 10.2 提交规范

提交信息应清晰说明本次修改内容，例如：

```text
完善团队门户成员资料管理
实现新闻文章分类及标签筛选
优化赛事中心及比赛详情页面
完成前后台认证体系及账户导航
完成后台公共布局及管理工作台
```

推荐在提交前执行：

```cmd
git status --short

git diff --stat

git diff --check
```

提交前应检查修改范围，避免将本地配置、测试数据及临时文件误加入仓库。

不要在团队共享分支上随意执行强制推送。

## 11. 安全与敏感信息保护

以下文件及信息禁止提交到 Git 仓库：

- `.env`
- 实际使用的 `*-local.php` 本地配置。
- 数据库密码及管理员凭据。
- API Token、cookie key 等敏感信息。
- Composer 依赖目录 `vendor/`。
- 运行时日志及缓存。
- 前后台运行时 `web/assets/` 生成内容。
- 临时数据库备份及测试文件。
- 个人 IDE 及操作系统配置文件。

可提交的配置示例必须使用明确的占位符。

项目使用 Yii2 提供的密码哈希、CSRF 防护、用户认证及 RBAC 权限机制。

正式部署时还应确保：

- 关闭 debug 和 Gii。
- 前后台 Web 根目录分别指向对应应用的 `web/`。
- 禁止通过 Web 访问本地配置、数据库脚本及敏感文件。
- 数据库账号遵循最小权限原则。
- 合理设置文件上传及运行目录权限。
- 定期备份数据库及业务文件。

### 13.3 常见问题

#### 数据库连接失败

检查 MariaDB 服务是否启动，以及数据库主机、端口、数据库名称和账号权限是否正确。

课程环境通常使用 3307 端口，但实际配置以本机为准。

#### 页面提示 cookieValidationKey 为空

检查 Yii 环境初始化是否正确完成，并确认前后台本地配置中存在有效的 cookieValidationKey。

不要将真实 key 写入仓库中的环境模板。

#### 后台登录失败或提示无管理权限

确认账号已经激活，并通过 RBAC 分配了相应业务管理权限。

普通注册用户不能直接登录后台。

#### 静态资源样式未更新

可以使用浏览器强制刷新，并检查 Yii AssetBundle 资源加载情况。

不要将运行时生成的 assets 文件提交至 Git。

#### Composer 安装失败

检查 PHP、Composer 版本及 PHP 扩展配置，阅读项目依赖兼容文档后再进行处理。
